# 🗄️ Guía de Administración: Supabase & PostgreSQL

Documentación del backend en la nube con Supabase, esquemas de tabla, seguridad RLS y tareas de limpieza automática con `pg_cron`.

---

## 📜 Script DDL de la Tabla `contact_messages`

Ejecutar en el **SQL Editor** de Supabase:

```sql
-- 1. Crear tabla de mensajes de contacto
CREATE TABLE public.contact_messages (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name TEXT NOT NULL,
    email TEXT NOT NULL,
    subject TEXT,
    message TEXT NOT NULL,
    environment TEXT DEFAULT 'production',
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 2. Permisos PostgreSQL para el rol público anon
GRANT ALL ON TABLE public.contact_messages TO anon, authenticated;
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO anon, authenticated;

-- 3. Habilitar Row Level Security (RLS)
ALTER TABLE public.contact_messages ENABLE ROW LEVEL SECURITY;

-- 4. Política de inserción pública
DROP POLICY IF EXISTS "Permitir insercion publica" ON public.contact_messages;

CREATE POLICY "Permitir insercion publica"
ON public.contact_messages FOR INSERT
TO anon, authenticated
WITH CHECK (true);
```

## 🧹 Limpieza Automática con `pg_cron`

Para evitar llenar tu cuota gratuita de base de datos, puedes programar tareas automáticas de mantenimiento en PostgreSQL:

### Borrar automáticamente mensajes de prueba (`development`) mayores a 24 horas:
```sql
CREATE EXTENSION IF NOT EXISTS pg_cron;

SELECT cron.schedule(
  'limpiar-mensajes-dev-diario',
  '0 0 * * *',
  $$ DELETE FROM public.contact_messages WHERE environment = 'development' AND created_at < NOW() - INTERVAL '1 day'; $$
);
```

### Vaciar manualmente mensajes de pruebas:
```sql
DELETE FROM public.contact_messages WHERE environment = 'development';
```
